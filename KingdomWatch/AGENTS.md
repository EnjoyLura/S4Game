# 交付要求

用户要求每次完成游戏改动后，都构建并发布到 https://kingdom-watch.pages.dev/，供手机浏览器体验。

使用既有 Cocos Creator 3.8.8 的 web-mobile 构建流程；每次构建后运行 `tools/patch-web-dpr.py`，完成相关检查，再通过项目现有 Wrangler 配置发布到 `kingdom-watch` 的 `main` 分支。部署后验证线上版本，交付可直接打开的游戏链接。具体命令见 README 的“构建与部署”一节。

Windows 构建用 `Start-Process -WindowStyle Hidden` 并将标准输出、标准错误重定向到 temp 日志，避免 Creator 的管道 EPIPE。若系统代理已启用，Wrangler 连接超时需在当前发布进程设置 `HTTPS_PROXY` 为系统实际代理地址；不要修改系统代理配置。

## 战斗特效经验

制作或调整战斗特效时先读 [冰系特效制作复盘](docs/冰系特效制作复盘.md) 与 `../美术/tools/AI视频特效工作流.md`。冰法师技能恢复用户认可的完整 v10（起手 0.4s、主体 0.42s、收尾 0.68s）：用户认为 v11 不如原版，勿再次默认使用代码切片坠落收尾。大招固定 128 颗全场随机错峰落冰，落点不依赖怪物位置；普攻复用同款冰晶，保留材质比例。视频只用 MiniMax H3，不使用 Seedance，不自动切换更贵模型。沿用用户指定的素材合成预览与人工战斗验收流程；用户后续明确指示优先。

## 主界面组件美术

用户选定“清爽漫画奇幻”：清晰深色轮廓、少量明确明暗、大块面材质和克制的细节。商店已采用 [商店漫画美术 v1](docs/shop-comic-v1/README.md)，风格参考、生产素材和实际提示词均保存在该目录。后续主界面组件优先复用 `ComicUI.ts` 的色彩、按钮状态和几何，插画沿用同一风格参考；不为各页单独设计资源栏。资源栏与底部导航继续五页共用。商店保持“大图 → 图标文字横排页签 → 三列商品”的游戏布局，文字与价格由代码渲染。

资源栏按用户最新调整紧凑靠右，商店标题跟随场景方木牌，商品区用全宽米色背板填满左右缝隙。组件只保留单层轮廓，勿恢复偏移底板和底部阴影条造成的叠片感；英雄招募头像使用 `comicPortrait` 正圆裁切，勿用椭圆底色承托浮空的半身图。

英雄页最新规范见 [英雄页漫画美术 v3](docs/hero-comic-v3/README.md)：用户认为 v2 删减过头，恢复方形英雄选择卡（卡内头像仍正圆裁切）、深色未选/金色选中背包分类页签、米色装备整栏背板与装备槽。保持页面标题移除、名字无底牌、场景只覆盖上半部、背包全宽纯色、空分类只显示居中说明不生成空槽位。场景参照用户认可的商店，以暖木梁、蓝旗与冷色窗景形成层次，勿再退回单一空墙色调；低圆石台中心仍需与立绘脚底对齐。左右切换采用完整圆石按钮，战力采用盾牌数字底板，勿恢复 v2 弯曲裸箭头与火焰布旗。属性、故事入口有深色底板并放大至 126×86，图标 46、字号 26，保证手机可读和触控。背包图标等沿用同风格插画；背包滚动记忆、全英雄已穿戴过滤和各弹窗继续可用。装备详情、对比不加外层框和关闭 X，保持点空白关闭。立绘仅用于英雄主界面，不替换战斗图集。
