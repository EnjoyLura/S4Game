# PNG 后续减重方案

本次先移除未使用资源，保留当前画面。v80 剩余运行包 448.49MB，其中 PNG 415.16MB（92.57%）；占比依然高，实际 PNG 字节已经比 v79 少225.92MB。占比本身不是目标，应同时看下载量、显存和画质。

## 实际素材样本

离线编码7份当前在用素材，Pillow12.3.0 / libwebp1.6.0，使用原尺寸；没有运行游戏。无损模式 `lossless=True, quality=100, method=4, exact=True`，逐份解码并比较全部 RGBA 字节；有损模式质量90、alpha质量100，透明通道逐字节相同。编码结果仅存放在本地 `.local-art-archive/png-compression-lab-v80/`。

| 素材 | PNG（MB） | 无损 WebP（MB） | Q90 WebP（MB） |
| --- | ---: | ---: | ---: |
| 雷法攻击图集，4096×3584 | 10.32 | 8.70 | 2.83 |
| 重弩攻击图集，4096×3584 | 8.06 | 6.69 | 2.07 |
| 冰技能完整 v10，3072×2304 | 4.40 | 3.37 | 1.64 |
| 火法强化图标，1254×1254 | 1.99 | 1.54 | 0.33 |
| 第一章战场，1152×2048 | 3.67 | 2.63 | 0.48 |
| 前哨地图，887×1774 | 3.38 | 2.74 | 0.65 |
| 强化卡底板，883×1477 | 1.64 | 1.18 | 0.09 |
| 合计 | 33.46 | 26.85（-19.8%） | 8.09（-75.8%） |

仅为这7份样本结果，不能按比例保证整包体积；Q90需要人工对比轮廓、色带、纹理与特效混合，文件更小不等于已通过画质验收。

## 推荐实施顺序

1. **先做无损构建编码。** 原 PNG 母版继续保留，生产构建为受支持设备导出无损 WebP，逐像素一致；逐个只采用比 PNG 更小的结果。通过 Cocos 纹理压缩配置或受控构建转换更新资源格式、原生扩展与哈希，不能只改文件后缀。检查目标手机浏览器支持及需要的 PNG 回退；若同时发布两种格式，网站总文件量可能增加，设备按能力加载的流量与站点总大小要分别统计。
2. **静态背景与插画单独选有损质量。** 无透明战场/地图可比较 WebP Q85～95 或 JPG；卡底板等大面积纹理先做 Q90 对照。保留原尺寸和九宫格边距，合成在深浅底色上查看。先确认静态大图，再决定英雄序列帧；不默认把全部图片有损转换。
3. **按真实显示尺寸审查大图。** 1254×1254卡图在卡面只显示约百余设计单位，可能有明显冗余；需结合设备像素比和物品详情放大尺寸决定最大导出尺寸。缩小分辨率会改变像素，先出对照，经用户选择后采用。英雄完整动作、不砍帧、不重排角色比例；透明留白若要紧密打包，必须同步修正帧矩形、脚底和采样边缘，作为独立改动。
4. **显存另做 GPU 纹理压缩。** WebP主要降低网络字节，不能把它当作显存优化：一张4096×3584 RGBA8图集约56MiB纹理数据，换成小得多的WebP后，解码尺寸仍相同。若手机内存仍高，再按设备能力评估 ASTC/ETC2、透明边缘质量与回退；支持情况和画质都需要手机确认。
5. **保持按需加载，并设资源准入。** 章节地图/怪物、英雄动作继续只请求实际需要的资源，后续可按章节拆 Asset Bundle。它能控制首屏/首次进关下载量，不能自动减少所有章节合计文件大小。废案、预览和母版始终放本地制作目录，只有当前采用的输出进入 `assets/resources`。

以上只有离线编码测量，本轮正式运行资源仍为原图、原格式和原尺寸。建议下一轮先实施第1步，再提供第2步的手机对照。

依据：[Cocos 3.8 动态资源构建规则](https://docs.cocos.com/creator/3.8/manual/en/asset/dynamic-load-resources.html)、[Cocos 3.8 纹理压缩与平台支持](https://docs.cocos.com/creator/3.8/manual/en/asset/compress-texture.html)、[WebP 编码与 exact/alpha 参数](https://developers.google.com/speed/webp/docs/cwebp)。
