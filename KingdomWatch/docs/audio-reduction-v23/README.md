# 音效精简第一版 v23

用户认为游戏的音效数量过多，希望先减少。此次调整实际发声时机、共用关系和并发预算，仍使用现有 v21 音源，不接入尚未选定的代表声音，不将旧版保留决定当作音质认可。

61 个代码音效定义收敛为 31 个可播放的独立入口：21 个静音、9 个转用其他入口。这不是“61条录音删为31条”，也不是实际播放次数减少49%的统计。旧定义、所有音频和元数据原样保留；未生效的声音停止预加载。逐项映射见 [61项用途处理明细](用途处理明细.md) 和 `source-inspection.json`。

| 场景 | 本轮处理 |
|---|---|
| 页签、英雄选择、列表切换 | 取消独立切换声 |
| 弹窗打开、关闭 | 取消开关装饰声；普通按钮仍可保留通用轻点击 |
| 设置、确认、普通成功、警告、三选一刷新 | 共用已有点击声；警告文字保留 |
| 三选一 | 保留卡牌出现和选中；取消前置战斗升级声 |
| 领奖、购买商品、招募英雄 | 共用现有奖励声，原奖励与招募展示保留 |
| 英雄、武器、技能、装备、主城普通升级 | 共用现有成长声；成功按钮取消额外点击声 |
| 长按连续升级 | 每步不发声，最近一次成功变化后约0.38秒集中反馈；突破优先，不补第二段成长旋律 |
| 升级/奖励数字落定、结算星星 | 取消装饰音，数字与星星动画保留 |
| 普攻 | 保留五英雄发射声；同组间隔至少0.12秒、最多2个声音并发，重点声音起音后0.24秒内发射声让位 |
| 命中 | 取消五种普通命中声；保留重击/暴击声音，同组至少间隔0.2秒、最多1个并发 |
| 技能、大招 | 保留角色辨识，自动技能同组至少间隔0.24秒，技能与大招最多2个并发；取消独立蓄力和就绪声 |
| 敌人死亡 | 普通怪不播；精英/BOSS共用厚重落点，同组至少间隔0.5秒、最多1个并发 |
| 来袭提示 | 普通大部队保留画面、取消声音；精英/BOSS保留警报 |
| 装备掉落、拾取 | 掉落出现静音；拾取保留，每0.6秒至多一次 |
| 胜利、失败、阶段突破、防线受击 | 保留原重点反馈；防线受击同组间隔和并发也受预算限制 |

音效总并发预算从14降至8（背景音乐独立），奖励/成长/卡牌各组最多1个声音；原主音量、背景音乐音源与音量、手势解锁、音效开关、后台静音、暂停与离场清理保持。原资源在磁盘/构建中保留，便于恢复。

十份原脚本有修改，`ComicUI.ts` 仅扩展按钮选项类型允许显式静音；其余脚本与所有音频/元数据的原散列保持。音效策略集中在 `AudioCatalog.resolveAudioCue`；UI仲裁先忽略静音装饰，避免它吞掉真正的点击/成功音。精英/BOSS死亡只修改传入音频的条件，不修改死亡表现、伤害、金币、经验、掉落或存档。

原文件快照在 `before/`，全量原脚本和音频散列在 `before.json`。只进行静态源代码核对、类型诊断对照、生产构建与引用检查；不运行测试、模拟、游戏、浏览器、音频播放或线上听感验收，实际体验待用户。完整工程仍有既有类型诊断，不能称全工程类型检查通过。
