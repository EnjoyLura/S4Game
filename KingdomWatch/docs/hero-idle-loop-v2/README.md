# 待机循环衔接修正与固定制作约束

2026-10-14，用户认可 `hero-idle-lively-v1` 的动作，但指出首尾跳跃、衔接不顺滑，并明确要求以后不再反复提醒首尾衔接约束。本次保留这版视频、全部动作帧和图集像素，只修循环播放时序，不重新生成视频或图片。

上一版按整体像素差阈值选择近似首尾，以末帧直接接回开头；用户实际反馈说明这种阈值不能代表自然衔接。本次删除通用打包入口的自动放行逻辑，默认采用全部选定原帧逐相邻帧往返、转折处减速、相邻帧闭合。末尾现在是第 1 帧接回第 0 帧，而不是重弩手第 49 帧／雷法师第 42 帧硬跳回第 0 帧。没有双图透明度过渡，避免此前黑闪、重影问题。

重弩手保留全部 50 张，播放顺序 `0…49…1`，共 98 项；雷法师保留全部 43 张，顺序 `0…42…1`，共 84 项。原单程约 3.076923 秒改为完整往返约 6.153846 秒，平均单程时长保留，转折缓和，不把两程强行压缩成一程时长。新正式资源 `sniper_idle_lively_loop_v2`／`volt_idle_lively_loop_v2`，显示高度 153／146、固定取景、脚底、武器握持和已认可动作像素保留。弓箭手原媒体、高度 185.64，以及重弩手攻击保持。

固定要求已经写入项目 `AGENTS.md` 顶部和 [英雄待机循环规范](../../../美术/tools/英雄待机循环规范.md)，并在 AI 视频工作流中关联：

- `generate_video.py` 对每次新待机任务自动追加 `hero_idle_loop_prompt.txt`，要求完整动作周期回到输入姿态、衣物轮廓和运动速度衔接，保留实际提交提示词；已有任务与提示词不改。
- 共享 `hero_idle_loop.idle_loop_timeline` 实际生成闭合帧序与逐帧时长，覆盖转折和循环边界，禁止非相邻帧跳回首帧。通用 `package_frames.py` 的旧 continuous／auto 请求同样进入相邻帧往返，不再用宽松差异阈值放行。
- GIF、预览和正式游戏读取同一份帧序与时长；一次性攻击不适用待机往返规则。

`fix_loop.py` 从认可版复制原图集并仅修帧表，另存新版本；全部原资料保留，新的源视频字段明确标记为沿用上一任务，不记作重新生成。用户认可原动作，不自动将本次循环修正记作视觉认可。

构建 Cocos web-mobile 后运行 DPR 补丁，`build_preview.cjs` 更新新入口 `hero-idle-loop-v2` 和旧 `hero-idle-lively-v1`／`hero-idle-subtle-v2`／`hero-stance-rebuild-v1`，`publish.ps1` 发布正式游戏。构建与部署记录见 `release.json`。按用户既有要求只制作、构建与发布，用户人工查看，不运行测试、浏览器、游戏或线上验收。
