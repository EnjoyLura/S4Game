英雄页与升级英雄页共用HeroLobbyIdle。此前静态立绘纳入UIArtReady，待机图集却在页面展示后独立异步加载；静态完整画布contain和待机visibleHeight/visibleWidth取景不同，晚到的待机会在玩家眼前替换成较大人物。TrainingGrowthFx没有在普通切换时缩放人物，页面过渡也只有横移。

本次让HeroLobbyIdle在configure时同步登记共享美术就绪请求，清单、图集和全部帧验证后，先设置最终尺寸/脚底、展示第一个动画帧、隐藏静态兜底，最后结束请求。英雄页和升级页现有refreshUI因此保留上一张完整页面，直到新人物首帧可绘制，再在after-draw交接；没有添加额外缩放或淡化。

加载失败、无效清单和组件销毁均结束等待；请求序号隔离旧回调。6秒超时先于外层8秒兜底，超时后本次显示保持静态，不让迟到图集重新换人，下一次页面刷新可使用已缓存资源。迟到/销毁回调取得的引用按原共享回调安全规则在微任务释放。不改变图片、现有动作、显示尺寸、锚点、技能与战斗规则。

此次发布包含此前仅本地完成的两位新英雄v105及八张已选强化卡。它们仍为静态人物/首版共享裁切图标；本次不将其记录为已完成动作。

## 用户追加的资源加载优化

- 五位有大厅动作的英雄直接请求实际清单/图集，共用缓存和在途请求；不再正常加载静态立绘再覆盖。静态图保留为失败/超时兜底，下一次刷新可使用已缓存动作。当前及下一位已拥有英雄预热可绘制资源，其余已拥有英雄下载实际动作文件/清单，不一次性创建所有大纹理。
- 大招按钮直接加载实际大招图标，失败时才请求其头像。三选一的头像经BattlePanelSkin映射到heroPortraitKey，原预热路径本身匹配，保留。怪物的BattleSprite/MobAnim复用同一uxFrame/引擎文件缓存，没有当成第二份网络图片误删；本次不改怪物绘制和死亡帧。
- 五页实际背景、所有可见英雄头像、全商店/装备/材料图标、已拥有英雄的技能图标、共享详情/暂停/结算美术、三选一卡池与字体提前准备。去掉商店仅前9项和背包仅前18项的预热截断。相邻可访问地图直接预热，其他已解锁地图/战场及图鉴已发现怪物图集/清单串行下载预取。
- 关卡页面选择时即准备当前与相邻已开放关卡的实际奖励、可用难度切换图标及敌人图集文件；战斗大图依当前选关/编队预热。普通页面资源和前台请求优先；远期大资源使用Cocos resources.preload只下载文件、不解析资产，不主动创建对应Texture2D；每次一个预取，隐藏/断网或有前台资源任务时让行。
- 战斗只创建上阵英雄对应的火/冰/雷/弓/弩特效池与加载器。入场提前准备实际普攻和攻击序列、所选英雄的特效图片/清单/材质、HUD、怪物、暂停/胜败横幅、强化卡，不再只预热待机、让第一发普攻临时获取攻击图。原0.9秒无条件揭幕放宽为6秒异常兜底；已预热入场保持原关门/开门及1.5秒节拍，资源就绪即可交接。

没有降低图片质量、减少选中英雄的画面特效、改变动画像素或追加美术资源。下载缓存、解码/资产缓存、已经上屏的资源区分处理；首次进入、刚解锁内容、慢网/断网和来不及预热的快速操作仍不能保证零等待，保持失败回退，避免无限等候或迟到切换人物。本轮静态检查不等于已在手机验证缓存命中率或实际帧率。
