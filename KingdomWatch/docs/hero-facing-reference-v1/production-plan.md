# 弓箭手瞄准与射击制作方案（尚未执行）

目标：参照用户录像中的固定站位、左右外观切换、局部持武器瞄准和短促射击反馈，保留用户确认的短棕发精灵与服装设计。仅借鉴表现，不使用录像中的游戏资产。录像不能证明对方内部采用哪一种动画技术。

用户已否定 archer-native-v1 的分层效果。该版本的独立手臂拼装和解析 IK 不作为后续美术基础；现有类型检查、动作计数与脚底测试通过不能代表视觉质量获得认可。本文件为制作方案，不代表游戏已修改或重新发布。

## 推荐制作方式

由同一位具备角色动画经验的美术／动画师在同一工程中制作瞄准与射击，导出完整人物的透明 PNG 帧。原画工程可复用身体、腿、头和服装图层；双手、弓、弦及搭箭在设计时整体校准。游戏运行时播放完整人物帧，不通过分别拉伸上臂、前臂来补救不成立的透视。

工具不限，可使用免费的 Krita。交付 PNG 和制作源文件即可，不要求用户购买 Spine。人工制作需要另行报价；先以单方向试做确定能否达到目标，不预付整套五英雄制作。

## 最小试做

只制作正前方、轻呼吸待机和一次普通射击。先画准备、拉满、放弦、回位四个完整关键姿势，再补有必要的中间帧。首箭从持弓准备姿势直接释放；持续攻击的准备动作由发射间隔安排。绘制帧数以动作连贯为准，不以达到固定数量代替质量检查。

检查：完整角色与确认形象一致；手指握持合理；弓弦连接两端及拉弦点，搭箭与瞄准方向成立；双肩与双臂无断接／穿插；脚底、人物比例和镜头固定；首次出手、连续出手与回位没有大幅姿势跳变；同时查看放大、逐帧、循环和真实 146 设计单位的手机画面。

## 扩展朝向

试做合格后覆盖左斜、左上、正前、右上、右斜五个瞄准区间，角度边界由真实目标范围和原画可承受的角度确定。五档是制作起点，并非宣称五张图就能实现连续转身。需要平滑转向的边界补过渡帧；不能靠大角度整图旋转或两张姿势交叉淡化掩盖接缝。

各角度从同一工程复用身体图层，保留准备、拉满、放弦、回位关键姿势。左右独立校准，保持左手持弓、右手拉弦；不通过水平镜像交换持弓手。若有允许镜像换手的后续用户指示，再简化素材范围。

## 源文件与标记

- 提议使用 512×512 RGBA 源帧；所有角度和动作使用同一画布、同一镜头、比例及脚底标记，武器留白充足。若画幅不足，全套一起调整。
- 同时交付绘制源文件、播放预览、帧时长与放箭标记。为关键帧记录箭尖／发射口位置，接入前与当前 HERO_Y + 60 起点校准，避免飞箭从身体中心突然出现。
- 图集统一裁切、缩放、留白与地面锚点；不逐帧自动居中。

## Cocos 接入责任

Codex 负责图集打包、姿态选择、角度缓冲、动作时序、释放同步、暂停、性能和手机验证。现有 fireRow／fireFanRow 回调及连射／箭雨规则可继续使用；替换视觉层，避免重复发射或改变攻速和伤害。

状态：持弓待机、准备、放箭、回位。换目标时对瞄准角度平滑并防止区间边界抖动；释放短阶段锁定当前姿态，随后过渡到新方向。0.12 秒连射保持举弓，按每排真实回调播放短释放／回位，不把完整拉弓动作压缩到每个 0.12 秒窗口，也不每排重置到松弛待机。

真人工检查原画与动作，工程检查发射事件与渲染锚点。先在独立预览中完成视觉与手机检查，再替换线上版本。源图质量不足时回到美术制作，不以代码测试报告替代视觉验收。

## 当前可靠性边界

Codex 可以负责接入工程与可复现验证。AI 生图可辅助构思／提供草稿；独立自动生成多角度、多动作帧的结构一致性和专业动画质量目前没有保证。达到用户要求需要合格的动作素材及人工校准；原生动画系统本身不能补救错误原画。
