# 美术加载与界面等待恢复 v150

用户报告大厅/战斗美术空白，主界面点击无反应。提供的手机比例截图显示文字、程序绘制的关卡旗帜和按钮底板正常，地图、货币及底栏图标缺失。只读检查用户已经打开的Chrome与应用内浏览器：当时两页都有美术，未读取到错误日志；没有刷新页面、点击按钮、进入战斗或启动新游戏。不能据此宣布手机故障已复现或已验收。

静态检查确认两个会导致持续等待的缺口：Cocos 3.8.8 DOM Image下载依赖load/error回调，没有截止时间；现有Service Worker在fetch响应头或响应体无限等待时，`pending`会一直保留该请求，后来相同图片也等待它。另有界面资源等待虽然8秒后结束，但随后的EVENT_AFTER_DRAW没有超时，会留下旧页面输入遮挡。

## 修复

- `ResourceDownloadRecovery`在场景建立、首批UI资源请求之前安装；包裹固定3.8.8引擎已有图片/JSON/字体下载器，保留ImageBitmap/DOM、解码及原重试流程。45秒截止释放引擎加载名额，原XHR也有同等超时；晚到的回调忽略，真实消费方异常继续抛出。读取版本固定的handlers getter有缺失保护，未覆盖音频处理器。
- Service Worker对响应头和完整响应体一起设置20秒截止，取消悬挂的网络请求后重试一次；最终失败释放共享pending。仍核对长度和SHA256，不让错误或不完整资源进缓存；未登记到版本清单的请求同样有截止。缓存协议/命名、保存位置和已验证资源保持，没有清空缓存或存档。
- UI绘制交接750毫秒仍未完成时也解除等待；超时时跳过需要后续渲染帧的过渡Tween，正常绘制仍用原动画。取消、销毁和更新候选页时撤销旧回调及计时器，避免旧回调覆盖新界面。

## 验证范围

`verify.cjs`用虚拟时钟和假网络执行实际的独立函数：永久无响应、响应体中途停住、取消信号、一次重试、pending清理、之后成功加载、SHA不符后重试、引擎名额释放、晚到/重复回调、同步异常，以及正常/缺失/替换/取消绘制交接均通过。未运行引擎、真实战斗、音频或WASM。类型检查相对7afe7e5a仍为原9条，无新增。
