# 重弩手斗篷出框修正

2026-10-14，用户截图指出重弩手斗篷末端超屏。问题来自原视频后段：768×1344 源片第 28～52 帧的披风已到右边界，缺失尖端；512×512 图集及 420×510 预览自身仍有空白，因此扩展画布或缩小显示无法恢复缺失像素。

本轮保留已认可视频及动作，不生成新图片或视频。`fix_cape.py` 对原 4～53 帧按完整人物源边界留白选择最长连续段，采用源第 4～26 帧共 23 张；头、武器、双脚和斗篷在此段距原视频边界均至少 12 像素。选中帧直接从旧图集复制，人物像素、固定裁剪映射、等比缩放、脚底 `(256,496)`、显示高度 153 不变，不缩斗篷、不局部形变、不逐帧居中或重新估计比例，不拼接不连续段。

相邻帧往返规则继续适用，23 张完整原帧组成 `0…22…1` 共 44 项，在转折处减速，循环边界第 1 帧接第 0 帧，不使用透明度交叉过渡。完整周期按原 50 张段的运动跨度缩短为约 2.762951 秒，保留平均动作节奏，不将短段拉长导致近乎静止。

新正式资源 `sniper_idle_cape_safe_v3`，图集 4096×1536。雷法师继续 `volt_idle_lively_loop_v2`，其像素和 6.153846 秒循环不变；弓箭手图片、待机、攻击、高度 185.64，以及重弩手攻击 `sniper_stance_attack_v1` 保持。

完整取景约束加入 `AGENTS.md` 与 [英雄待机循环规范](../../../美术/tools/英雄待机循环规范.md)：视频提示词自动追加全运动范围留白要求，通用打包入口在固定裁剪之前调用 `hero_frame_bounds.require_source_margin`，源人物距四边不足 12 像素即拒绝，不能靠扩大透明格子掩盖源视频出框。与首尾循环闭合约束一同自动应用。

原视频保持作为制作记录，预览明确提示原片后段出框，修正效果看上方 Canvas 和 GIF。新预览入口 `hero-idle-cape-fix-v3`，旧 `hero-idle-loop-v2`、`hero-idle-lively-v1`、`hero-idle-subtle-v2`、`hero-stance-rebuild-v1` 同步更新。构建 Cocos web-mobile、DPR 补丁与 Wrangler main 发布记录见 `release.json`。

源帧范围、各源帧边界及剔除依据见 `../sniper-idle-cape-safe-v3/cape-framing.json`。这些是素材制作记录，不构成动画验收；按用户要求不运行测试、游戏、浏览器或线上验证，由用户人工查看本次修正。
