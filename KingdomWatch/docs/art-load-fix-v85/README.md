## 报错原因和修复

`Ux.ts`新增的可见范围监听会在节点销毁时清理一次，图片回调返回时又清理一次。Creator3.8.8的 `Node.off`直接访问事件处理器，节点析构会清空这个引用，因此第二次清理会触发截图里的 `Cannot read properties of null (reading 'off')`。已按本机引擎源码核对销毁顺序。

清理现在有一次性标记；销毁回调不再解绑自身，异步完成只对严格有效的节点操作，所有等待者仍独立结清。滚动优先级、图片去重、原界面和动画继续保留。

切换VPN或断网会打断图片、脚本、清单等请求，浏览器的联网状态也不一定随VPN变化。原模板把所有 `console.error` 和未处理Promise都显示为红色代码错误，放大了正常下载失败的干扰。现在：

- GitHub入口的清单/入口下载各最多尝试3次，单次20秒超时，重试间隔1/2秒；普通4xx立即停止，408/429/5xx可重试。没有自动刷新循环。
- 入口仍失败时显示中文原因和重试按钮；收到联网事件可以重新尝试尚未启动的入口，防止并发启动。
- Cocos既有下载重试结束后，UI图片最多再尝试2次。短时断网保留队列，联网后继续；离线等待30秒后未开始的请求结清，保留程序占位，避免永久持有已关闭页面。
- 仅识别明确的下载/图片错误和同源脚本、图片、样式资源失败，改为可关闭的网络提示；保留控制台诊断。真正的代码异常仍显示，未用宽泛的TypeError过滤掩盖程序错误。
- SystemJS下载失败时，入口不再继续调用未定义的System而产生第二条错误。引擎启动脚本彻底失败后，需要点击“重新加载”。已经加载的内容可继续使用，未下载内容仍依赖网络。

正常启动继续隐藏旧的“王国守望/正在校验运行入口/托管诊断”界面。独立诊断页、入口哈希、子路径和版本检查保持。
