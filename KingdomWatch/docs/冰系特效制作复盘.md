## 这次真正有效的方法

### 先把参考拆成具体要求

参考 GIF 提供的是运动和节奏，静态图片提供的是冰晶造型与材质。还必须明确游戏内的显示尺寸、俯视角、地面接触点、怪物遮挡关系与透明度。参考本身足够有用；之前的问题在于制作时没有把这些要求一起兑现。

本次需要的是贴地、连续、克制的冰系游戏特效。细节丰富的大冰面静图直接盖到地面上，仍会像一张贴纸。大星芒、长时间爆发、晶体反复变形会增加动画片和 AI 演示的观感。

### 连续运动来自视频，精确控制交给代码

本次一次生成多格序列帧的方案出现了晶体形状、位置与裂纹变化，播放时抖动明显。后续有碎裂、寒气等连续运动的素材，默认从一段连续 AI 视频提取真实帧，不靠独立生图拼时间轴。

代码负责固定位置、空间映射、显现遮罩、轨迹、分层和时序。AI 负责冰晶的切面与碎裂运动。需要精细材质的主体优先用通过的图像素材，简单光点与漂移可以用代码补充。

### 认可的素材优先修，避免整段反复重生

用户对 v6 的评价约为 80/100；主要问题是轮廓不圆和起手太动画。最终通过的是对这段素材的定向修正，而不是重新生成的 v8。

把反馈映射到最小的修改：轮廓问题修空间映射，播放慢修逐格时长，突兀修起手，透明度问题修混合与取景。只有晶体材质、运动本身或镜头不可用时，才重新生成相关素材。

### 稳定取景比增加帧数更重要

整段使用同一个联合裁切框、缩放、地面锚点和空间变换。禁止逐帧按包围盒重新居中、重新缩放或单独“圆化”。否则冰晶会漂移，地面会呼吸，增加帧数也解决不了。

左右不圆不能只归因于镜头距离。先检查源视频是否裁边、实际画幅是否符合请求、轮廓是否本来就是多边形。本次圆度处理对所有帧共用一套固定映射，保留原有运动。

### 起手要有可见过程，不能仅淡入完整成品

v9 的 40ms 淡入仍被用户认为突然出现。v10 改成中心小冷光 → 结霜向外传播 → 冰晶从根部显现，随后衔接原视频。晶体保持原来的形状与位置，避免尖端先悬空出现。

最终用户要求把起手增加到 0.4 秒、收尾增加到 0.68 秒。可调逐格时长比把整个视频统一加速更有效，也不必为节奏调整再次调用 AI。

## 固定制作流程

1. 明确已有伤害、控制和持续时间，再定义画面，避免视觉承诺一种实际不存在的控制效果。
2. 写出材质、视角、地面中心、占画幅比例与起手/峰值/收尾。视频只用 `lens-minimax-h3-768p`，不使用 Seedance，不自动更换更贵模型。
3. 首批做一个独立的 2 秒视频元素。黑底、固定俯视镜头、主体完整入画、四周留白；不要同时生成角色、地图和 HUD。
4. 检查实际分辨率、帧率和总帧数，不假设接口一定遵守画幅或时长。本次纯文本生成 v6 成功，参考图片是否作为接口输入应按素材需求决定。
5. 固定取景抽帧，保留原始顺序。校正黑场；当前工具的 `alpha=max(R,G,B)` 提取方式需要反预乘 RGB，输出直通 RGBA，并使用标准透明混合。这是本项目黑底素材的提取约定，不适用于所有 AI 图像。
6. 先在最终游戏尺寸上合成：地面、怪物、伤害字、技能特效。每帧固定位置，GIF 共用调色板；按累计边界量化 GIF 的 10ms 时间单位，保持总时长。
7. 交付接触表、峰值静帧、动态预览，由用户人工确认。按用户要求，不进入真实战斗进行浏览器自动检查；后续最新指示优先。
8. 确认后接入：战斗时钟、等比尺寸、固定锚点、对象池、场景清理、全透明末帧。伤害与控制由战斗代码管理，特效结束不改变状态。
9. 完成类型检查、Creator 构建、DPR 补丁、线上入口及资源核验，交付带版本参数的游戏链接。

## 必须避免的复发问题

| 现象 | 优先检查与处理 |
| --- | --- |
| 序列在抖，冰晶变来变去 | 换成连续视频来源；排除逐帧居中、缩放、透视校正 |
| 像不透明的大贴纸 | 减少遮盖；核对黑场、反预乘与透明混合，不用 ADD 播放当前 RGBA 图集 |
| 亮得发白，细节消失 | 排除重复叠层与混合方式错误，再调整局部亮度；不统一压暗所有素材 |
| 完整冰面突然跳出来 | 补真实的显现过程，让地面与晶体根部先出现 |
| 起手过于电影化 | 剪掉长星芒与慢爆发，保留短冷光；按阶段重设时长 |
| 左右边缘平直、尖端缺失 | 检查原片裁边、画幅与形状；整段固定校正，必要时重新生成该元素 |
| 空白边距导致游戏内太小 | 按地面有效半径或主体宽度缩放，不按整格宽度当作技能范围 |
| 暂停后特效还在动 | 使用战斗模拟 dt，避免独立 Tween、系统时间或视频播放器驱动 |

## 下一步

2026-10-11 v11 人工验收结论：用户认为不如原来的技能，要求换回。已恢复完整 v10，保留 1.5 秒时序与冻结/减速/伤害配置。代码切片虽然符合向下重力轨迹，但合成切分、同步坠落和静态主体改变了原视频的连续消散观感；物理参数正确不能替代视觉验收。该方案仅保留为实验，不能把 v11 当作认可基线。普攻这轮复用大招冰晶材质，按原比例、弹道方向和模拟年龄绘制蓝白尾迹，不追加 AI 生成。见 [普攻与强化卡更新](frost-normal-v1/README.md)。

2026-10-11 最新录像明确了大招的空间语义：用户需要“天气式全场冰棱雨”，不能按怪物分布来决定落点。v3 以怪物附近为主的 72% 定位会让上方怪群吸走落冰，中下段空缺。v4 固定 128 颗，8 个宽纵深区域各随机生成 16 点后全体打乱；大小碎裂均绑到这些雨滴自己的地面接触，不依赖怪物。随机也要保证全场覆盖，但不要采用可见网格或按区域逐排发射。验证相同种子下不同怪物分布产生完全相同的雨计划。见 [大招 v4](frost-ultimate-v4/README.md)。

同轮反馈指出普通技能的原视频收尾有向上喷散的运动。v11 沿用 v10 起手和主体，只把成熟帧的冰晶拆成固定材质碎片，赋予向下初速度和重力，接地后再消散；原地寒气单独淡去。不能通过整张贴图下移、反播或提前淡出来代替碎片落地。认可的连续视频仍可按阶段保留；局部物理错误可以用固定碎片和可复现运动纠正，无需再次生成整段。见 [技能 v11](frost-field-v11/README.md)，这轮视觉质量待用户人工战斗验收。

2026-10-11 大招第三轮反馈：上一版依然假，出现位置、视角不协调，而且数量过密；用户明确要求先后落下。v2 把所有冰棱绑到一条屏幕上方生成带，导致不同深度目标的路程和速度不同；主冰棱同时出现、材质呈双尖菱形，又全部盖在怪物上方，容易像移动的二维覆盖层。仅增加数量、加速和碎屑不能解决这些空间问题。

v3 改为各自地面落点投影空中高度，加入小幅远近尺寸和速度切线方向；材质沿用现有尖端与宽肩，去掉双尖的菱形感；冰棱与角色按地面深度一起排序。数量降至最多 96，少怪继续减量，全部独立错峰发出；主落冰穿插到整段时间内，对应地面视频缩至 0.68 秒，接地才逐点碎裂。经验是分别检查“最大数量、瞬时同屏数量、出生与落地的时间分布”，不要把池容量当作画面密度，也不要把所有主要目标集中在起手时发射。制作记录与实际渲染状态合成见 [大招 v3](frost-ultimate-v3/README.md)，最终质量等待用户人工战斗验收。

2026-10-11 大招第二轮反馈：冰棱雨不像从天而降，也不像砸到地面，落冰与碎冰太稀。检查发现原代码只在落点附近短程匀速移动，而且接地前淡出，碎冰更早独立出现。更换素材不会修复这类空间和时序错误。此次用代码让冰棱从战场上方进入、加速下降、尖端定位、到地才碎裂；补落点阴影、短闪光、裂纹与有回落过程的冰屑，将落冰提高到 128 枚、主要碎冰提高到 24 处。没有追加 AI 视频。

后续制作落地特效时，必须统一“空中轨迹终点、素材尖端锚点、地面反馈起点、碎裂触发时刻”。不要靠提前淡出来掩盖落地问题，也不要让碎冰和飞行物独立计时。增加密度需要补每次落冰的接地反馈，不只增加空中数量。离线预览现在从实际 TypeScript 渲染器导出状态再合成，避免另一套近似运动模型和游戏实现不一致。新流程和预览见 [大招 v2](frost-ultimate-v2/README.md)。

2026-10-11 大招首版反馈：全场传播寒潮与本游戏不搭。按用户要求删除整片寒潮与旧扩散波纹，保留冰棱雨、脚边碎冰和局部消散寒气后接入。后续冰系全场效果优先通过落冰密度与分散命中表达范围，按具体反馈决定是否增加整片地面传播层。

冰法师大招的方案、分层、时序与首个视频提示词见 [极寒领域大招制作方案](frost-ultimate-v1/README.md)。这次通过的是技能特效，不把 1.5 秒或圆形底图当成所有大招的固定模板。
