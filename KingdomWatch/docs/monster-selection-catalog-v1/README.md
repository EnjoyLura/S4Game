# 怪物形象选择与实际使用图鉴

直接用浏览器打开本目录的 `index.html`，无需服务器或联网。原图目录另有快捷入口：`C:/Users/user/Pictures/KingdomWatch/怪物图鉴.html`。

## 游戏实际使用（2026-10-23）

页面顶部有 **游戏实际使用 / 候选图鉴 / 四宫格** 三个入口。首次更新后默认打开实际使用区，之后记住最后查看的入口和实际使用章节。可以切换「全部章节」或各章分栏，全部条目仍在一页连续显示。

- 当前项目配置共 **16 章、86 种现用怪物**：前哨 8 种、深林 8 种，其余各章 5 种。其中 15 种使用已接入的行走序列帧。
- 每张现用卡片展示游戏当前图集里的独立形象，标记普通怪、精英、关底 Boss、近战/远程/治疗及飞行；序列帧角色显示帧数。15 种已接入动画的怪物可点「播放动作」，支持暂停、0.25/0.5/1/2 倍速、回到首帧、拖动定位和逐帧查看。14 种使用独立强化立绘的 Boss 可切换常态与强化形态。
- 「复制本章清单」或「复制当前怪物清单」包含游戏 ID、实际名称、定位和现用图片路径，便于继续讨论替换；本地剪贴板不可用时提供可选文本与 TXT 下载。
- 实际使用的章节归属来自当前 `ChapterContent.ts`、章节出怪配置及召唤/分裂关系；图片来自 `enemyArtRef` 对应的游戏图集。原来的候选选用、章节分配、备注、归档、回收站与 JSON 备份继续使用原存储键。

`live/monsters/` 保存 86 张常态 PNG 和 14 张强化形态 PNG，共 100 张；均按游戏清单的矩形原像素裁切，保留 RGBA、画布和透明留白，不重绘、不改比例。`live-catalog.json` / `live-catalog-data.js` 记录章节、实际 ID、帧数、图集矩形和 SHA256。文件直接以 script 加载，可在 `file://` 下离线打开，不依赖 fetch、服务器或外链。

更换正式怪物素材或调整章节后，运行本目录 `sync_live_catalog.py` 可重新同步。脚本只读取配置文本、JSON 图集清单及 PNG；不导入 Cocos、不运行游戏或出怪模拟、不读取游戏存档、不构建发布。候选编号与整理记录不参与重建。本轮仅本地图鉴更新，线上游戏发布状态以对应发布记录为准。

## 怎么挑选

1. 全部形象在一页连续显示，不用翻页；列表缩略图随滚动加载。搜索外观或编号，按主题、原图集筛选；点击图片放大，用左右箭头连续查看。
2. 点「选用」加入清单。详情中可填写章节、兵种定位和备注；填写这些内容也会自动选用该形象。章节使用当前游戏的 16 章名称，也可以先不分配。
3. 点「复制所选清单」，直接粘贴给开发助手。每只都有固定编号，例如 `S24-06`，能准确找到对应 PNG 和原图位置。也可保存 TXT。

选择与整理记录会尽量自动保存在当前浏览器。用「导出整理备份」保存 JSON 后，可换浏览器再导入；章节、备注、归档、回收站状态一并保留。兼容此前的选择备份和已保存在浏览器中的勾选记录。右侧批量分配章节会作用于清单中的全部已选形象。

## 归档、删除与批量整理

- **候选区**：正常挑选的形象。每张卡片和放大详情都有「归档」「删除」。
- **已归档**：暂时收起，还想留着比较的形象。可恢复到候选区，也可以删除。
- **回收站**：明显不合格的形象点「删除」后移到这里，从正常候选中隐藏。恢复时回到删除前的候选区或已归档。
- 点击 **批量整理**，使用卡片上的独立勾选框，再点归档、删除或恢复；支持勾选当前全部筛选结果。整理勾选与右侧的「我的选择」独立，变更筛选后只保留仍在筛选结果中的整理勾选。
- 放大详情中归档或删除后，会自动继续显示下一只，适合逐只筛选。操作后提供「撤销」，也可随时从对应区域恢复。
- 归档和删除保留章节、备注与原先的选用标记；恢复到候选区时还原。已归档和回收站中的形象不计入右侧选用清单及复制结果。它们的章节与备注可查看，恢复后可继续编辑；「恢复到候选区并选用」可一步完成。
- 所有整理都是图鉴中的状态记录，不删除硬盘上的原图、独立 PNG 或缩略图。编号始终保持不变。

取消选用保留备注，清空选用只作用于当前候选区清单；清空和导入备份也提供短暂撤销入口。浏览页面很长时可点右下角「顶部」回到筛选和归档入口。

## 素材整理

- 输入目录共 66 张图；其中 3 张与其他文件逐字节相同，图鉴保留 63 张独立原图，重复文件名记在 `sources.json` 的 `aliases`。
- 共裁出 **627 个候选条目**。同一题材在不同图集中仍分别保留，方便比较造型；没有按怪物名称合并。
- `monsters/`：627 张独立 PNG，保持原图分辨率和对应区域像素，不放大、不重绘；原来的背景保留。
- `thumbs/`：仅用于列表浏览的 WebP 缩略图；放大详情和「打开独立 PNG」使用原像素裁图。
- `sources/`：63 张原文件的字节副本，输入目录中的原图没有修改。
- `catalog.json` / `catalog-data.js`：稳定编号、临时外观名称、原图文件名、行列、裁切坐标和 SHA256。详情中的「查看原图集」可显示对应位置。
- `crop_plan.py`：逐图布局与非等分图集的单独边界。少数原画本来贴近边缘或互相交叠，裁图保留实际原画；需要确定最终素材时可对照原图。
- `inspection/`：原图总览与非标准布局裁切检查图；`crop-report.json`：裁切数量、像素一致性校验记录。

候选区的外观名称只是检索标签，不是定稿的种族、技能或章节安排，是否采用由用户选择。原始 63 张图集 / 627 个候选之后，已按用户选择追加 S64 至 S66，目前候选区为 66 张图集、633 个形象；与 86 种游戏现用条目分开展示。

## 校验与后续

初版已检查图片文件、所有引用、元数据、裁图像素及 JavaScript 语法；本次单页与整理功能改动追加检查语法、HTML 引用和旧记录兼容路径，素材与编号保持。未启动游戏或浏览器进行运行验收，页面实际交互由用户挑选时体验。后续章节选图可直接按清单编号定位，不必重新描述外观。

实际使用分栏的静态检查记录见 `live-validation-report.json`：章节/角色引用、100 张图片像素、脚本语法及 DOM 引用；浏览器交互由用户刷新原页面后确认。

裁切脚本使用 Python 和 Pillow。需要重新生成时，在本目录运行 `python prepare_catalog.py --crop`，会沿用已有 `sources.json` 与编号。不要因追加图片而重新执行完整库存编号；新增图集应在现有编号后继续增加，避免已分享清单失去对应关系。
