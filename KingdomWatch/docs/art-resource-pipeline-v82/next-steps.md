# 下一阶段的具体处理依据

本阶段只发布无损编码。以下项目已经有静态依据或本地对照，未将估算记为已取得的内存/帧率收益。

## 1. 英雄图集紧密排布

审计394张PNG和37份可识别帧清单，发现9张基础RGBA8纹理达到32MiB，其中8张英雄动作图集4096×3584，各56MiB。静态逐帧alpha包围框，保守保留每侧4px余量后的面积估算：

| 图集 | 帧矩形面积可减少的估算 |
| --- | ---: |
| 重弩攻击 | 50.58% |
| 重弩待机 | 44.68% |
| 雷法待机 | 41.06% |
| 冰法待机 | 40.86% |
| 火法待机 | 39.70% |
| 冰法攻击 | 39.18% |
| 火法攻击 | 38.12% |
| 雷法攻击 | 35.64% |

这是每帧包围框面积之和，未包含排布损耗、图集整尺寸和过滤要求，不能直接宣称纹理显存按此比例下降。当前播放器以固定画布、groundAnchor和SpriteFrame矩形控制比例，直接裁图会跳动。下一轮应先给帧数据增加原画布/裁剪偏移，离线还原每帧与原稿逐像素比较，并保留原帧数、时长、释放帧、脚底和镜像。轮廓外围要保留过滤余量并检查边缘颜色外扩，防止线性采样串色；完成这些之后再接入播放器和重新排布，不默认缩小人物或删帧。

## 2. 静态大图的有损候选

`tools/art-resource-previews.py` 生成4份仅本地Q90候选和对照页：

| 素材 | 原PNG | Q90 WebP | 减少 |
| --- | ---: | ---: | ---: |
| 第一章战场 | 3.67MB | 0.48MB | 86.8% |
| 前哨地图 | 3.38MB | 0.65MB | 80.9% |
| 火法卡图 | 1.99MB | 0.33MB | 83.3% |
| 强化卡底板 | 1.64MB | 0.09MB | 94.8% |

百分比相对原PNG，不能叠加到已经采用无损WebP的收益。Q90尺寸和alpha字节相同，RGB有损；需要人工查看渐变、纹理、轮廓和深浅底合成。当前未替换正式资源。

## 3. 图标导出尺寸

76张达到1024以上的方形PNG被列为显示尺寸审查候选，并非全部判定冗余。选卡面板 `Panels.ts` 的卡图盒为124设计单位，头像48单位；但要把局内强化、物品/图鉴详情、图标复用和实际设备缩放全部纳入上限。

项目DPR适配可达到4倍及桌面模式补偿，不能按统一2倍直接缩图。按每张图最大实际显示物理像素确定512/768等候选尺寸，生成手机对照后选择。当前所有导出尺寸保持。

## 4. 加载与释放

`BattleEntryWarmup.ts` 已按当前章节与出战英雄预热，优先复用其入口。`HeroSequenceAnimation.ts` 的clips Map及显式addRef、`Ux.ts`的全局SpriteFrame缓存和`MobAnim.ts`的动作缓存需要一起管理；只删Map或直接releaseAll可能造成仍在界面、图鉴、下一场预热中的图片失效。

下一轮应建立公共UI/英雄/章节的资源使用范围：先建立真实使用者与异步加载的引用关系，复用公共图，退出范围后仅释放无人使用的资源。分包迁移还要保留当前动态加载ID、检查跨包依赖与共享图不重复。此轮保留现有生命周期，未执行破坏性全量释放或把“分包”当作包体减少。

GPU格式ASTC/ETC2等在尺寸与生命周期明确后再按手机能力、透明边缘质量及兼容回退评估。WebP仍是网络格式，不能替代这部分内存工作。
